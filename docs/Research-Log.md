# Research Log

> Source: GitHub Wiki — `shin584/Demand_Forecasting_Program` (page: Research‐Log)
> Local copy for offline reference. Last synced: 2026-09-16.

## English Summary

Design research covering: which DB columns/tables map to which model features, derived variables (drug-exhaustion date, medication-delay days, MPR adherence score, chronic/acute classification incl. pseudo-labeling for the ~30% of prescriptions missing a disease code), external time-series factors (weather, holidays, flu-season indices), the "two-track mapping" design that avoids a sparse per-customer × per-drug matrix by splitting into a visit-probability table and a per-customer drug-profile table, and modeling decisions (tree-based models over deep learning given ~45k prescriptions, negative sampling for class imbalance, 3-way train/val/test temporal split, sample weighting for severe/chronic patients, and a rare-drug 100%-allocation rule to avoid stockouts on low-volume drugs).

# 파생 변수 및 외부 요인

## DB 내부 데이터 기반의 파생 변수
* **예상 소진일 및 복약 순응도 패턴** (tbl매출 조합)
  * 예상 약 소진일 = 내방일_N + 조제일수_N
  * 복약 지연일수 = 내방일_(N+1) − 예상 약 소진일
    * >0: 복약 지연 발생 / =0: 완벽한 복약 순응 / <0: 조기 방문(예: 장기 여행 준비)
  * 복약 순응도 지표(MPR) = (Σ조제일수) / (최종 내방일 − 최초 내방일 + 최종 조제일수) × 100
* **만성/급성 질환 방문 분류**
  * tbl처방전.질병분류기호 ↔ tbl처방병명.병명코드 연결로 라벨링
  * 10만 건 처방전 중 약 70%만 질병분류기호 라벨링됨 → 나머지 30%는 추가 라벨링 필요
    * 후보 방법: 투약일수 임계값 분류, 특정 타겟 약품 유무 역산, 진료과목/의료기관 특성, 과거 방문 이력
    * **채택 방향:** 라벨 있는 70%로 조제일수·진료과·약품코드 등을 변수로 삼아 가벼운 분류 모델(Random Forest)을 학습, 나머지 30%를 예측해 채우는 **Pseudo-labeling**
* **노쇼 이력**: tbl매출의 다음내방일 대비 실제 미방문 횟수/비율로 다음 방문 확률 보정

# Two-Track Mapping

## '고객 단위 표'에 약품 정보를 넣을 때의 문제점 (차원의 저주)
환자 1명이 1회 방문 시 보통 3~5종의 약을 처방받음. '고객 1명 = 1줄' 표에 다 넣으면:
1. 약품마다 칼럼을 만들면 (약 3,000종) → 칼럼 폭발, 희소 행렬로 학습 불가.
2. 한 칸에 텍스트로 우겨넣으면 → 수량을 수학적으로 계산 불가.

## 실무 해결책: 투트랙(Two-Track) 매핑 구조
표를 하나로 합치지 않고 **1) 내방 예측 표**와 **2) 처방 프로필 표**를 분리, 예측 단계에서 두 값을 곱함.

1. **내방 예측 테이블**: 특정 고객이 내일 방문할 확률(%)을 ML로 계산. 예: C001 → 90%(0.9)
2. **고객별 기본 처방 프로필 테이블**: 방문 시 확정 소진되는 약품·수량 매핑 (`tbl조제약품.소모량` 활용)

| 고객ID | 약품ID | 약품명 | 1회 내방 시 평균 소모량 (낱알) | 주요 질환 약품 여부 |
| :--- | :--- | :--- | :--- | :--- |
| C001 | D_001 | 아스피린장용정 | 30 | Y (만성) |
| C001 | D_002 | 크레스토정 (고지혈증) | 30 | Y (만성) |
| C002 | D_050 | 코대원포르테시럽 | 15 | N (급성) |

## 최종 재고(수요) 예측이 이루어지는 과정
1. 모델이 C001 고객 내일 방문 확률 = 0.9(90%) 예측
2. 프로필 테이블 조회 → C001은 오면 아스피린 30알, 크레스토정 30알
3. 기댓값 계산: 아스피린 += 30×0.9=27알, 크레스토정 += 30×0.9=27알
4. 방문 확률이 있는 모든 고객의 기댓값을 약품별로 합산 → 내일 약국 전체 '약품별 확정 수요(총수량)' 도출

# 모델링 포인트

## 알고리즘 선택
* 최근 3년치 처방전 데이터 약 45,000건 → 딥러닝엔 부족(과적합 위험)
* **XGBoost, LightGBM, Random Forest** 등 트리 기반 모델 채택

## 클래스 불균형
* 전체 데이터는 실제 방문 기록뿐이므로 정답=0(미방문) 데이터도 학습에 필요
* 특정 고객 전체 기간 데이터를 만들면 미방문이 압도적으로 많아짐 → 모델이 "무조건 안 옴"으로 수렴
* **네거티브 샘플링**: 의미 있는 오답만 남기고 나머지는 버림
  * 초기(1~5일차, 약 넉넉): 1개 샘플링
  * 중기(15일차, 약 절반): 1개 샘플링
  * 말기(27~29일차, 헷갈리는 구간): 2~3개 샘플링
  * 결과: 정답:오답 ≈ 1:5, 무조건 0 예측 시 정답률 80% 이하로 떨어져 모델이 정상 학습 시도

## 검증 데이터 분할 (3단 분할)
* **Train (2년 치):** 학습용
* **Validation (그다음 6개월 치):** 중간 검증, Early Stopping
* **Test (최근 6개월 치):** 최종 성능 평가

### 계절성(Seasonality) 고려사항
최근 6개월 테스트셋은 1년 중 '절반 계절'만 반영됨.
* **만성질환 (Track 1):** 계절 영향 적음 → 6개월 테스트로 충분
* **급성질환 (Track 2):** 계절성 뚜렷 → 통계 기준은 '과거 3년 치 동월(같은 달)' 전체 데이터를 사용

## Two-Track 수요 합산 방식
1. **확정적 수요** (내방 예정 고객 기반): 고객별 내방 예측 확률 × 최근 해당 약품 소모량
   * 예: C001 방문확률 80%(0.8) × 고혈압약 30정 = 24정
2. **통계적 수요** (요일/환경 기반): 과거 동기간/동일 요일 평균 소모량 + 외부 요인 가중치
   * 예: B약품 월요일 평균 100정, 기온 급락 가중치 +20% → 120정
3. **최종 수량** = 확정적 수요 + 통계적 수요, tbl매입품목의 최소단위수량으로 나누어 박스 단위 발주량 산출

## 학습 가중치 (Sample Weight)
"이 환자를 틀리면 재고에 큰일 나니 3배 더 집중해서 맞춰라"는 의미로 강제 부여.
1. **중증/산정특례 여부 (최우선, 3.0~5.0)**: TBL매출의료급여자격조회의 중증암등록대상자/산정특례중증난치등록대상자/산전산모대상자 중 하나라도 'Y'면 1(Yes)
2. **만성질환여부 (2순위, 2.0)**: tbl조제약품.총투약일수(장기 처방) 또는 tbl처방병명.병명코드(고혈압/당뇨 등) 기준, 조제일수 30일 이상 등

## 재고 부족 상황 회피 방안
1. **다빈도 약품 → 대수의 법칙으로 상쇄 (그대로 기댓값 사용)**
   * 예: A약품(30정) 방문확률 80% 환자 10명 → 기댓값 240정, 실제 8명 방문×30정=240정 (일치)
2. **희귀/소수 약품 → 임계값 100% 할당 (로직 분리)**
   * 환자 1~2명뿐인 특수약(항암제, 희귀 자가면역질환제 등)은 기댓값 곱셈 시 품절 위험
   * 방문확률이 임계값(예: 0.3) 이상이면 곱셈 없이 필요 수량 전체(100%) 확정 반영
3. **안전재고(Safety Stock) 최종 가중치**
   * (만성 기댓값 + 급성 통계 수요) × 1.2 (20% 버퍼) 또는 최소단위수량 기준 올림(Round up)
* **구현 결론:** 약품별 '타가는 환자 수'를 먼저 카운트 후 분기 처리
  * 5명 이상: 기댓값(확률×수량) 합산
  * 5명 미만: 확률 ≥0.3이면 100% 할당

### 실제 학습 시 병합된 데이터 행렬 예시
`model.fit(X, Y, sample_weight=Weight)` 실행 시 모델이 바라보는 형태:

| [X] 나이 | [X] 성별 | [X] 가족_총내방 | [X] 남은_약_일수 | [X] 내일이_예약일 | [X] 만성질환 | ... | [Y] 내일_방문 | [Weight] 가중치 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 65 | 1 | 12 | 1 | 1 | 1 | ... | 1 | 2.0 |
| 28 | 0 | 2 | -2 | 0 | 0 | ... | 0 | 1.0 |
| 55 | 0 | 8 | 2 | 1 | 1 | ... | 1 | 2.0 |

* 이론상 학습 데이터양은 365×3×환자 수이나, 네거티브 샘플링 적용 시 훨씬 줄어듦.

# 시스템 추론 작동 프로세스

1. **기준일자(T) 스냅샷 촬영**: 내일 날짜 기준, 오늘(T) 시점 DB를 조회해 학습 때와 동일한 [Mart 1] 형태 표를 실시간 생성.
   * C001: 약 1일 남음 / 내일이 예약일? Yes
   * C002: 약 5일 남음 / 내일이 예약일? No
2. **모델에 입력**: 새로 계산된 환자별 데이터(나이, 성별, 남은 약 일수 등)가 모델의 실제 Input이 됨.
   * "C001은 65세, 내일이 예약일, 약 1일 남음 → 내일 올 확률 90%"
   * "C002는 약이 아직 5일 남음 → 내일 올 확률 5%"
3. **재고 기댓값 연산 (곱셈)**: 각 환자의 내방 확률에 [Mart 2: 최근 처방 프로필]을 매핑해 기댓값을 곱하고, 내일 발주할 총량을 계산.
